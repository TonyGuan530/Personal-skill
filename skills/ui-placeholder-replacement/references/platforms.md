# 平台适配

只读当前平台一节；表中是接入关注点，不是强制API或固定版本。先看项目实际栈及其文档，沿用现有实现。

## 微信小程序与小游戏

首先分清WXML小程序和原生Canvas小游戏；不能互换两者的输入与验证方式。

### WXML/WXSS

- 保留button/input/switch等控件语义、绑定和可访问能力；外观可用原生样式、独立装饰层或素材背景。
- 适配现有rpx/px策略、安全区、系统字体缩放与小屏；图片fit/fill/crop须按用途决定。不要靠固定屏幕截图坐标布置所有元素。
- 装饰不吞触摸。检查禁用态、长文字、滚动区及遮罩层；用项目支持的小程序自动化和开发者工具验证。

### Canvas小游戏

- 核对逻辑像素、设备像素比、画布缩放、相机与触摸坐标换算。命中框、素材锚点、动画形状来自同一布局来源，避免各写一组近似数值。
- 绘制支持真实alpha、源图集frame、必要切片；分包独有资源必须在可用后再引用，保留正确加载/失败表现。
- 抽取/爆炸/转场等期间隐藏按钮时，同步撤销热区，防止旧帧回调提交动作。按现有渲染调度请求动画帧，结束即释放，避免长期无意义全速重绘。
- 使用项目允许的CLI、MCP或自动化进行真实Canvas触摸/截图。WXML selector、直接dispatch、浏览器模拟不等于小游戏真输入/真机验证。

## Godot

- 沿用实际版本、Control容器、锚点/offset、最小尺寸和主题体系。优先复用Theme、StyleBox、NinePatchRect、TextureRect/TextureButton等适合的原生资源；不为一套皮肤改引擎或节点架构。
- 普通框体可用StyleBox；装饰纹理按适用方式切片。TextureButton多状态对齐可见边界、透明留白和枢轴，禁止切状态跳位。
- 资源文件、导入设置、过滤与压缩一起检查；像素画和细描边的采样需求不同，不通用强制最近邻或某种压缩。导入后看目标尺寸及透明边缘，不能只看源PNG。
- 装饰Control不拦输入（按现有mouse_filter/事件传播约定设置）；保留键盘/手柄焦点、禁用态及触摸。可见图形与点击mask/控件热区的差异必须有意设计。
- 聚焦、hover、按下、禁用等不一定共享同一张纹理；外圈高亮需匹配当前状态及节点变换。动画退出、节点释放和重新进入场景后不残留Tween/信号/输入锁。
- headless启动或解析检查不能证明画面合格。至少在实际项目渲染器中看运行截图；真机、目标导出平台与性能证据另列。

## 网页

- 保留DOM语义与原生交互：按钮、链接、输入、错误提示和开关不能成为只有图片点击事件的div。可见文字保留为文本，焦点可见、键盘可用。
- 代码几何、SVG、CSS适合简单控件；生成图片适合插画、材质和复杂异形外观。使用背景/遮罩/伪元素时，让装饰pointer-events不阻塞真实控件。
- 响应式布局先解内容与容器关系，再加材质；测试窄屏、桌面、长标签、字体缩放和必要的高DPR，避免只适配一张参考截图。
- 检查object-fit、SVG viewBox、九宫格/边框图片、圆角裁切和透明边缘。阴影、高亮不改变点击层；不要把CSS外接矩形冒充异形轮廓。
- 动画沿用项目运动规范；适用时支持减少动态效果偏好。循环装饰停止后不再持续调度，前后台/卸载后无泄漏。
- 用真实页面与浏览器自动化截图/输入验证；组件预览与静态HTML不证明完整路由和加载正常。

## 其他框架

映射同一契约：资源加载 → 可见边界 → 布局/切片 → 状态 → 输入 → 特效轮廓 → 运行证据。采用框架已有主题、布局、可访问与动画生命周期，不复制某个平台的坐标或API。
