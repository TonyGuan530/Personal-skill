# Placeholder UI 成品化

主要处理**程序化画出来、还像临时线框的按钮、底板和框体**：默认描边矩形、简单圆角底色加文字、缺乏成品层级的选项槽等。流程是 **判断 → 生成或复用 → 接入 → 自检 → 定点修正**。将它们转成适合项目画风的生产皮肤，而不只是把线框换个颜色。不是把每一个矩形都变成贴图，也不是只交一张整屏效果图。

## 使用边界

- 用户标出的元素是重点，但先读取截图、组件实现、已有设计规范、素材和状态；静态截图无法证明完整交互。
- 默认保留产品功能、文案含义、已认可画风、布局职责和平台。不要把本技能来源项目的古风、配色、特定引擎或发布流程套给别的项目。
- 标准输入框、文字和清晰的扁平控件可能已是合理设计。若用户明确要求全图形化，解释可编辑文本、焦点和语义仍需原生/代码层承载，完成其视觉要求；不要静默缩减范围。
- 已授权的局部替换直接推进；只有缺少必要素材、风格方向冲突、规则或功能不明确时提问。不要因每一步生成都要求确认。
- 优先项目可用的素材/设计工具；需要位图插画、纹理、异形组件时使用可用的图像生成或编辑工具。已有SVG、原生主题、代码几何适合的元素继续用对应方式。工具不可用就说明缺口，不用代码伪造“已生成”。
- 用户明确要求为临时线框“生成样式”时，默认交付可接入的按钮/框体皮肤素材；除非已有合格主题或用户选择代码原生方案，不以另一套默认描边圆角矩形冒充完成。动态标签、布局和输入逻辑仍留在代码层。

## 1. 判断：建立最小替换清单

按完整的一个屏幕/流程识别候选，优先阻碍理解、层级混乱、明显粗糙的部分。一个局部问题不自动升级为全应用重做。

| 决定 | 依据 | 交付 |
| --- | --- | --- |
| 保留 | 已符合画风、信息与交互清楚 | 简短说明即可 |
| 代码调整 | 间距、排版、简单边线、状态、原生控件问题 | 主题/样式/布局修改 |
| 复用 | 现有成品素材语义与尺寸适合 | 运行引用及适配 |
| 生成/重绘 | 缺少主题插画、材质、图标或异形外观 | 独立可接入素材及状态 |
| 待判断 | 无证据、风格未定或影响功能 | 具体不确定项 |

常见占位迹象：用户指出的程序化线框、与已认可界面不相配的默认边框、一排相同底色矩形缺少材质与主次、临时图标/空插画、无层级的同尺寸按钮、假禁用遮罩超出边界、文案溢出、缺少选中/加载/错误状态。**程序绘制、简单、灰色、圆角本身不是占位证据**；有意采用的成熟扁平设计可以保留。

每项只登记后续需要的信息：组件/页面、问题、处理决定、运行路径、显示尺寸范围、状态、文字层、输入范围、验收方式。复用现有清单；没有时可用 [记录样例](references/record-example.md)。

## 2. 生成：生产组件，不生产截图替身

先确定角色与层级：主动作、次要操作、设置选项、展示面板、危险/禁用状态分别承担什么。对同一系列统一材质、光线、角度、线条粗细和视觉重量；不要把同一华丽纹理铺满所有控件。

- 保留已有构图基准；缺少基准时先做一个代表组件，检查后再扩展成系列。用户已给出明确方向时无需追加审批。
- 按**用途、比例、透明要求、状态**分组。背景/插画单独生成，小图标可成组，异形按钮与面板按可延展区域制作。
- 动态文字、价格、数量、状态标签通常由代码绘制；静态烘焙文字只在用户明确选择且语言/修改成本可接受时使用。不要把按钮变成包含假文字与假交互的整屏图。
- 透明对象要求真实alpha，不能把白底/棋盘格/绿幕或PNG扩展名当透明证据。生成后检查暗底、亮底和实际背景；边缘去污染不能吞掉细线、指尖或金属边。不要通用强制二值alpha，避免锯齿。
- 提示词必须包含用途、已认可参考、目标显示比例/尺寸、材质/视角、内容安全区、透明/不透明、文字策略及状态要求。横幅须按横幅重构主体，不把竖版封面直接裁切成横幅。
- 保留来源图，运行用图另存，记录真实引用。只修失败组件，不因单项出错重做所有资产。

可改写的提示词骨架：

> 为[产品/画风]制作[组件/插画]，用途[角色]，实际显示[尺寸范围/比例]。参考[已确认参考]，保持[材质/光线/视角]。主体[构图与安全区]。文字由代码绘制，请勿加入文字、数字或UI示意。背景[真实透明/完整不透明]。状态[所需差异]。需要[可延展中段/固定端帽/九宫格安全边]；不要[已被否决的特征]。

## 3. 接入：素材、布局、输入一起校准

接入前按项目阅读 [平台适配](references/platforms.md) 对应一节。没有目标运行环境时仍完成可验证部分，并标明剩余缺口。

- 素材放入所属模块/分包/资源目录，检查下载或导入时机、引用路径、压缩与实际包体；不能只留在生成器的临时目录。
- 区分源图尺寸、alpha可见边界、显示尺寸、装饰范围和命中范围。按可见主体计算“放大30%”，不要把透明留白当按钮。若命中范围有意不同，记录原因并验证，不让新增可见区域误导玩家。
- 新边框会消耗内容空间：重新计算内边距、字号、行高、自动换行、图标基线和相邻间距。长文案/大字号不能靠整体挤扁控件解决。
- 九宫格的源边距与显示边框分别设定；端帽/装饰等比，只有合适区域延展。太窄/太宽时换专用布局或代码方案，不拉扯角花。
- 状态至少覆盖实际存在的正常、按下/选中、禁用、加载/错误。禁用外观沿同一形状制作；不能用一个矩形灰遮罩溢出异形按钮。
- **高亮、波纹、描边、遮罩与按钮共用形状/轮廓、锚点和变换。** 尖角签牌不能套椭圆光圈；状态轮廓不同则使用对应遮罩。装饰不抢输入、不漏到邻居。
- 动画由真实状态驱动；隐藏同时撤销输入，渐出中的不可操作元素也不能继续点击。恢复、切页、重开、失焦/后台后的计时与清理都要检查。
- 只改呈现时不改规则结果、价格、资源或网络提交。美术替换不能新增隐形动作或改变操作结算。

## 4. 自检：看到成品在运行中成立

按 [自检与返修](references/self-check.md) 做与改动相称的验证：先查文件/alpha/坐标，再检查真实组件与完整界面，最后验证输入和状态。组件拼图用于初筛，不能代替完整页面截图或目标平台运行。

每个已替换项必须回答：是否仍像占位？是否符合现有风格与信息层级？是否挤压文字/改变尺寸？轮廓与特效是否一致？输入与视觉是否对应？适用状态是否都检查？

发现问题回到对应组件：构图错则重绘，边缘错则修alpha，形变则改切片/布局，信息不清则调排版，点击错则修输入。不要靠提高整屏亮度、盖遮罩或隐藏错误来“通过”。生成重试以具体缺陷为单位；连续两次无改善时改变方法或说明阻塞，避免无目标反复生图。

## 交付

简述玩家可见变化、运行素材路径、检查范围和未验证项。证据区分：素材检查、组件渲染、完整界面、目标平台、真机/设备性能。没有测帧时间就不能声称60fps；截图合格不等于交互合格。

不默认发布、收费、启动网页反馈服务、调用特定平台工具或要求用户承担全部QA。技能不授予额外权限。已有项目流程优先；局部修改可短交付，整套替换附清单与剩余项。
