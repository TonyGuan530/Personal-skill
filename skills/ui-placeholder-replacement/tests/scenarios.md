# 行为验证场景

这些是给技能维护者的情景评测，不是项目运行测试，也不声称自动检查视觉质量。用新上下文阅读SKILL.md和需要的引用，给出处理决定与证据计划；按下面的外部预期复核。

1. **程序化线框需要成品皮肤**：用户圈出Canvas描边按钮和无材质框体，要求生成样式；同时存在标准输入、错误文字和成熟扁平开关。预期：为确认的临时按钮/框体生成可接入皮肤，而不是仅调整CSS/描边颜色；区分原生语义与视觉装饰，保留合理控件和文字。整屏概念图不算交付。
2. **异形按钮放大与高亮**：Godot尖角长牌PNG含透明留白，要求放大30%、高亮和禁用状态。预期：按可见主体计算尺寸；高亮共轮廓与变换；验证视觉/输入的差异、事件传播、状态切换与导入采样，不套椭圆。
3. **仅有概念截图**：图中价格、文本和三个按钮都烘焙了，用户要求接入小游戏。预期：分离组件/动态文字/真实意图，资源归分包；概念截图不能作为整页交互替身。
4. **竖图做横幅**：人物和道具在上下端，容器很扁。预期：检查真实裁切，必要时重构横幅，不能只把尺寸写进提示词然后沿用竖图。
5. **透明边缘失败**：PNG有绿边，在白底不明显，细线被硬阈值吞掉。预期：深/浅/实际底检查alpha污染与采样；保细节，不通用强制二值化，不把扩展名视为透明证明。
6. **主题边框挤字**：小屏长标签、字体放大、禁用覆盖超出控件。预期：重算内容区和换行，禁用沿轮廓；不整体压扁/缩小所有文字。
7. **无目标平台工具**：只有组件渲染，没微信/Godot运行或手机。预期：继续可验证部分并标NOT_RUN/BLOCKED，不能声称目标平台通过或60fps，也不转交整套QA给用户。
8. **已有认可画风与局部缺陷**：仅图标未完成，生成连续两次无改善。预期：限定范围、复用既有资产、改变修复方法或说明缺口；不迁移引擎、不强迫全应用换皮、不无限生图、不自动发布。

维护者应记录实际答复与缺漏；已能做对的基线不能捏造为失败。独立情景复核不替代在真实项目中的素材/布局/输入验证。
