# 引擎和工具适配

通用的是职责、交接和证据要求；具体命令、资源格式及测试方式必须来自当前项目或对应版本的官方资料。

## 建立足够用的环境事实

从已有说明、工程文件、锁文件、构建脚本和实际工具可用性获取下列事实，已有记录只核对变化。信息未知就标为未知，不为一项小修改扫描整个机器。

| 项目事实 | 需要确认的内容 |
|---|---|
| 技术栈 | 引擎／自制运行时、版本、语言、关键插件及版本约束 |
| 交付目标 | 平台、输入设备、显示规格；性能敏感时补目标设备和预算 |
| 运行入口 | 项目、场景或程序入口，启动命令或实际编辑器操作路径 |
| 构建与测试 | 项目已有构建／检查命令、返回结果、日志位置；无 CLI 时记录替代操作 |
| 编辑边界 | 可编辑源文件、二进制场景、生成文件、资源引用 ID 和导入流程 |
| 可用能力 | 文件／CLI、编辑器 API 或 MCP、UI 操作、屏幕／音频检查、目标设备 |
| 验证边界 | 哪些可运行，哪些只能静态检查，哪些需要设备或人工体验判断 |

先使用可靠的项目命令和已连接的工具；需要引擎专门知识时使用当前可用的相关技能或官方文档。缺少某项技能并不要求安装该技能才能继续。不要假定环境支持浏览器、无头模式、截图或资源生成。

## 按项目条件执行

- **有 CLI 的工程**：用已核实的版本和项目命令；参数不确定先查帮助。退出成功只证明该命令的检查范围。
- **主要依赖编辑器／可视化脚本**：通过可用的编辑器 API、插件或 UI 操作修改；检查节点、事件连接、序列化引用和运行效果。没有可用控制工具时清楚说明受限部分。
- **二进制或不透明资源**：使用对应工具编辑，保留源资产与导出配置；不要把任意二进制当文本修改。共享场景和工程设置由单一负责人写入。
- **网页或自制运行时**：沿用现有构建与启动流程，捕获控制台／进程日志；检查资源加载、输入、实际游戏循环。不得为了套模板替换技术栈。
- **无引擎的新项目**：根据平台、玩法、现有安装、用户熟悉度和交付时间提出最少必要选项。明确授权自主选择时记录依据后执行，不将偏好的引擎写成通用默认。
- **目标环境缺失**：尝试已有构建、CI、测试替代路径；它们只能证明实际覆盖内容。需要额外安装、账号或设备才能继续的部分记录阻塞，其余工作继续。

“工具无关”不表示任何工具都已测试兼容。更换引擎版本、导入器、平台或构建设置后，重新检查受影响资源和交付包。
