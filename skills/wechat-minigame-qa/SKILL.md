# 微信小游戏自动化 QA

把规则、会话、输入、渲染和工具通道分别验收。规则模拟完成不代表交互顺畅；截图静止、RPC 超时或 CLI 成功均不能单独证明游戏健康或卡死。

## 测试范围

读项目指令、project.config.json 的 compileType/miniprogramRoot、Git 状态与工作树，识别待测游戏和真实入口。记录版本、差异、设备、基础库、种子和命令。保留其他聊天的工作树与 IDE 窗口；不默认全局 quit、清缓存或杀共享进程。已有测试先复用。

验收：大厅进入 → 准备/规则 → 开局 → 核心操作和关键分支 → 终局/结算 → 返回/重开；加入连点、动画期间输入、无效动作、恢复存档及前后台切换（项目具备时）。开发入口开放不等于正式发布授权。

## 通道选择

读 [工具与 SDK 接入](references/tooling.md)，按当前能力选择，不固定排斥 UI 自动化：

- **wechatide 桥（MCP 或 CLI）**：版本支持时用 automation_game_action、automation_evaluate、simulator_screenshot；小游戏不用 WXML selector 或页面导航。逐项限时验证；wx 可求值也不代表应用入口已启动。
- **Airtest/Poco**：Airtest 图像识别适合 Canvas 外部点击。Poco 提供语义控件树，自制 Canvas 需要 SDK 适配。用户允许 SDK 接入时可按官方接口接入，不把接 SDK 本身当阻塞。
- **node 规则/会话测试**：人数/种子/难度/时间矩阵，验证终局、非法动作原子拒绝、资源守恒、计分与边界。独立预期来自规则说明和手算例子，不用同一算法验证自身。
- **同一 Canvas 的浏览器补验**：可验真实场景输入/渲染与截图；明确标为浏览器，不能冒充微信模拟器或手机结果。

## 卡死与顺畅度

同步 JS 死循环会阻塞 setTimeout、Promise.race 与进程内耗时检查。把测试放进子进程，由外部监督器设墙钟期限；只终止自己创建的 worker。使用 [run-bounded.cjs](scripts/run-bounded.cjs)：

```powershell
node <skill>/scripts/run-bounded.cjs 60000 <report.json> node <test-script.cjs> <args>
```

另设最大步数和无有效进展次数，失败保存种子、动作轨迹和最后 state。日志有界低频，不连续提交已知非法动作灌爆 console。等待用户、暂停和倒计时各用合理期限；相同快照或无效点击不直接判死锁。虚拟时钟扫矩阵，真实会话/动画/计时另验。

真实交互必须证明**输入接收 → 状态按预期变化 → 画面反馈**。诊断 SDK 应分别记录输入序号、状态版本、update/draw 次数；日志心跳不能代替主循环证据。量化顺畅度记录样本数、输入到反馈的 P50/P95/max 和帧耗时；工具往返耗时不是游戏响应耗时。

## 规则与体验

每步检查轮次/阶段/资源范围、守恒、非法动作拒绝后关键状态不变、重复提交、终局结果不变、存档恢复。多策略/座次/种子报告局长、死局和胜率；AI 自对弈不能证明真人平衡或好玩。规则审计独立读规格与实现，默认不重写玩法。

云项目核对客户端/云函数副本一致及相关本地/联网行为；本地结果不当作云端通过。测试请求不自动授权上传部署。

## 交付

按层报告 PASS / FAIL / BLOCKED / NOT_RUN，列复现步骤、版本、日志/真实截图和边界。分类：游戏 bug、规则/体验待判断、环境故障。结论用“本版本在指定场景与时长内未观察到卡死”，不保证永不死锁。

QA_AUTOPILOT/stress/tour 等开关收尾恢复 false，检查实际文件与 git diff。不默认制作反馈网页。脚本与 SDK 必须实测；格式校验不等于行为验收。
