# 桌游移植：初始化大礼包与上线门禁

把已确认规则变成可玩的数字桌游，并把容易遗漏的产品功能从第一天纳入范围。已有游戏按证据补缺，不推倒重做。规则可结局、功能已接入、独立验收、主线合并和正式上线是不同状态。

## 先选择范围与阶段

读项目入口、真实分支/未提交改动、规则版本与改编表、认可美术、公共服务接口及现有验证。优先当前用户决定；旧聊天是需求和经验来源，历史完成声明不能证明当前构建通过。

确定首发模式：单机人机、同机轮流、在线多人可组合；扩展、云存档、付费/兑换另列能力。仅设想的功能标DEFERRED，不因清单存在就新增联机/付费/农场。已经承诺的首发功能不能改标N/A来绕过缺口。

|阶段|最低交付|可以保留什么|
|---|---|---|
|B0 初始化|规则/换皮映射、能力与占位登记、模块/公共服务边界、资源计划、验收责任；可启动的开发入口与诚实降级|未接功能用明确禁用状态和接口契约；不是可玩完成|
|B1 内部可玩|准备→合法选择及所有必选子阶段→自然终局/同分→结果→返回/重开；有效操作反馈、错误出口、适用保存/暂停/AI|受控开发范围内可保留登记过的美术、教学、音频占位；不得挡住合法动作或伪装成功|
|B2 发布候选|首发范围功能真实接通、主题资源到位、独立规则/输入/数据/适用联机验收、目标平台证据和例外登记|仅与首发无关且隐藏/明确未开放的未来入口；必要功能占位阻断发布|
|B3 上线就绪|完成适用发布清单、实际版本/包/权限/回退核对及最小人工体验；发布授权单独确认|通过就绪检查不等于已经部署或获准公开发布|

初始化或补缺先读 [必要功能矩阵](references/capability-matrix.md) 与 [初始化与占位合同](references/bootstrap.md)；要上线时读 [发布清单](references/release-checklist.md)。不为局部修改加载所有参考。

## 从规则到实现

1. **规则真源。** 固定已选版次/扩展/勘误，记录可核查来源与原文位置。把原名→新主题、人数、组件、阶段、合法动作、信息权限、费用/收益、终局与同分对应到实现/验证。混用来源须显式登记；缺失的规则不从概念图、AI策略或测试直觉猜。重大规则歧义询问，独立工作继续。
2. **初始化产品外壳。** 沿用现有目录和引擎，实现准备/规则帮助/菜单/返回/加载失败/结果的最小导航；建立能力与占位清单及可用接口。公共UI/房间/存储/权益复用宿主，不各游戏复制。规则、AI、会话、呈现、资源和宿主适配职责分开，按实际边界拆分，不按文件行数机械重构。
3. **生产素材。** 已认可设计直接拆分；缺设计才探索。按 [素材生产合同](references/art-production.md) 逐件大图、成组小图集，文字/动态值/状态由代码处理；允许项目明确选择烘焙固定牌名，但须确认规则版与可本地化边界。每件有运行路径、尺寸/锚点/alpha/坐标/预算。不得以整屏概念或少量样本代替素材完成。
4. **玩法与表现闭环。** UI只提交合法意图，规则负责结算。动画消费已确认事件，不反向改变规则结果；查看说明不暗中跳过回放，跳过演出不跳过动作；最终动作先可理解地呈现再展示终局。未知写入结果不报成功、不改成新动作重试。规则/教学/本机菜单暂停与在线全桌暂停分别定义。
5. **按完整流程交包。** 一个owner可包内多步实现、自测和提交；依赖与共享文件负责人明确后再并行。默认不要求每个helper单独派验。独立QA有实际候选再开展，复用未变证据，修复集中回收。人数/并发/主动回报机制遵循项目当前授权，不在skill硬设代理或定时任务。
6. **验收与交付。** 用 [开发接入与证据层级](references/completion.md) 和发布清单验适用范围。实际触摸、目标平台、真实身份/网络、手机音效/性能不能由直接dispatch或浏览器截图替代。只让用户做少量必要smoke与主观体验；缺环境说明最小协助，不转交整套QA。未知/受阻继续留缺口，不能宣布全游戏完成。

## 可直接使用的初始化资源

优先复用项目现有记录；首次初始化可运行：

```text
python scripts/init_boardgame.py --project-dir <项目路径> --game-id <稳定英文ID> --title <游戏名> --mode solo-ai --mode hotseat
```

默认仅预览；加`--write`才建立`docs/games/<game-id>/`的brief、rule-map、capabilities、asset-plan、release-checklist。可用`--output-rel`指定已有文档目录，目录须在项目内；已有文件完整保留并提示跳过。它只生成登记/工作模板，**不声称已实现功能**；继续按B0实现原生外壳/接口和已授权阶段。模板在 [assets](assets/game-brief.md)，具体生成语义见bootstrap。

## 项目适配与边界

- 微信Canvas、CLI/MCP、包体、真实身份、工具禁用与QA暂停服从该项目当前入口；能力不足才标BLOCKED，不偷偷更换验证层并称通过。
- 现有音效、存储、房间接口可复用不代表消费者已经接通；必须验证实际调用与失败路径。缺公共能力先登记并协调owner，开发占位可用，首发相关门槛不能因此消失。
- 规则/素材来源和公开发行权利须有负责人及核对记录；购买/CDKEY/奖励兑换只在该首发范围适用时进入独立门槛，不自动开通。
- MentatBG项目使用 [本项目配置](references/mentatbg-profile.md)，通用项目不要照搬其等待秒数、画风或当前技术路线。经验来源见 [对话与审查提炼](references/source-lessons.md)，不是现行政策或测试证明。
- 已有授权覆盖的普通实现不追加批准步骤；真实交易、云部署、发布、跨聊天消息等仍遵循用户授权。使用skill不授予这些权限。

交付时简述实际阶段、可玩入口、剩余占位、适用门禁、独立证据/未测、版本与下一整包。清单数量或测试数量不计算“完成百分比”。不默认网页报告/新服务/新聊天。
