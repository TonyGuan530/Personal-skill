# 上线前的判定方法

复制 [发布验收模板](../assets/release-checklist.md) 到项目，先填首发模式与候选客户端/服务端/资源/规则版本，再逐项判适用性。每项有PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE、证据、owner；未测不能算通过，N/A须说明为何不在首发承诺。

## 放行条件

- 规则错误、越权/秘密泄漏、资金/权益错误、丢失用户数据、卡死或不能自然终局为阻断。其它问题按实际影响分级，P2也可能是本项目明确发布门槛，不能只按严重级别自动跳过。
- 首发必要功能的placeholder、假成功、无效按钮、无限加载、无法退出、无法完成必需选择应先解决。非首发功能隐藏或明确未开放后可延期，不能临时把首发承诺改成N/A。
- 已有通过证据绑定未变代码时可复用；注明继承的候选范围。改动影响规则/会话/输入时重验相应消费者和完整路径，不重复全仓测试刷计数。
- 发布候选至少有独立验收。开发自测、PM审代码、独立QA、平台实际运行、用户smoke分别列，不把同一个实现者改角色名当独立QA。
- 用户只做必要体验判断。人工步骤给候选、入口、设备/人数、几步操作、预期/停止条件和未测项；不能要求其承担整套多人边界测试。
- 合并、测试环境部署、体验分发、正式发布、真实交易各自遵循现有授权。清单勾完不自动触发云部署/收费。

## 必测组合按风险选择

**所有游戏：** 合法人数/玩法变体、必选子阶段、无效动作不变性、自然终局/同分/分项、最后动作呈现→结算→返回重开、菜单/信息查看/连点、资源失败、最窄/最短支持窗口、高DPR、安全区、保存失败/坏旧档（若支持保存）、进出与后台、音效实际播放/静音、长局性能。

**在线：** 不同身份/座位视角；快慢混合（可用1秒、1/2/3/5分钟边界，具体按游戏配置）；已提交者等待不催；断网/后台/暂离/正式退出分别；单人失联与全员失联；AI提交与收回先后；回包丢失、重复requestId同/异意图、乱序、同房新局同version、多设备旧连接、房主变化；正常终局一次与同桌再开。隔离权威服务/时钟验证广覆盖，再用获准真实身份/环境检验实际云与平台链路。暂停24h的虚拟边界不等于24h真机耐久。

**商业化/兑换：** 所有检查在本次启用时才适用。价格/商品/资格从可信服务端；通知与发货幂等；未支付/取消/未知/退款不伪成功；权益与单局资格、进度分离；CDKEY权限/次数/重放/已拥有处理；跨设备与订单对账；可篡改本地结果不直接成为付费资格。具体平台政策临近启用时查当前官方材料，不把本skill当法规或交易授权。

## 证据缺口与结论

可写“内部可玩，待平台验证”“发布候选，尚有阻断”“已满足本次上线检查，待发布授权”；不能由数百个单测、CLI success或几张静图推断已上线或全链路可靠。静图看布局；视频看动画时序；音频/目标设备检查声音与性能；实际权威库/网络记录证明联机与写入结果。缺工具先保存有效层证据并交可继续的候选，受影响发布门禁保持未通过。
