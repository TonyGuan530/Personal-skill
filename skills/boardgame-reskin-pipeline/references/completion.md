# 开发接入与验收

有现成游戏时仅补缺项。规则与素材清单是不同合同：美术不改规则，规则测试不代替美术接入。

## 接入顺序

保持现有引擎；微信原生Canvas项目继续使用原生Canvas。新游戏代码和素材归独立包，主工程只挂窄接口。下载成功后才require游戏模块和读分包图片；失败可恢复，重复点击复用同一加载请求。目标平台解析规则需实际核查，例如微信目录require不等于Node的index解析，JSON坐标清单也不能假定可直接require；必要时生成目标平台支持的模块，并核对与生产清单完全一致。正式环境门禁不能被缓存开发卡片或场景绕过。

具备合法动作接口时让UI完整展示并提交引擎动作，包括奖励卡、骰子后处理、目标/子集选择、对手回应、最后计分与余卡阶段。不能只实现AI会选的路径。游戏有存档时验证必需阶段字段、合法版本与资源范围，坏存档安全拒绝；终局后的连点不得命中刚出现的重开并覆盖结果。

## 必要证据

| 层 | 通过证据 | 不足以通过的证据 |
|---|---|---|
| 规则 | 选定版本独立核对、手算边界、费用/容量/卡与棋子守恒、终局和同分 | 不明版本的旧模拟次数 |
| 正常对局 | 多人数/种子合法操作自然达到原规则终局；保存最短复现 | 测试强塞资源、固定QA回合数宣判赢家 |
| 会话/输入 | 准备、全部必选分支、无效动作、连点、恢复、返回/重开实际触摸 | 仅直接调用引擎dispatch |
| 资产/画面 | 生产路径和图集坐标正确、实际场景加载、真实尺寸可读与热区对应 | 概念图、素材拼图、Node绘制上下文替身 |
| 目标平台 | 正确工作树实际编译运行、关键交互和截图/运行日志 | CLI返回success、浏览器截图、静止画面 |

验证程度按风险和改动选择；不把“实机暂时不可用”当作丢弃可试玩分支的理由。PASS / FAIL / BLOCKED / NOT_RUN分别列出，旧游戏既有失败单列，不隐藏。无需为每个可逆文案/像素调整加镜像测试。无新疑点不反复跑已通过全仓测试。

## 评审通道

先遵守用户当前允许的评审工具。用户禁用computer-use/CUA时，只用授权的CLI、MCP/bridge、无头脚本与隔离上下文；不借浏览器补验绕过限制。用户要求等待统一QA时，交付开发版本、截图与已有日志，不主动启动新的QA轮次。记录更新前已经完成的证据及版本，避免将旧截图冒充新版本通过。

## 工具受阻

先证实项目窗口、实际游戏上下文与版本；wx API可求值不代表目标游戏已启动。接口调用设外部墙钟看门狗，同步死循环不能靠同进程setTimeout终止。只结束自己创建的测试worker，保护共享IDE与其它对话。同一无进展调用最多首次尝试加一次有针对性的复核；没有新证据或状态变化不再重复。保留日志，改用确实可用的验证层。修复了明确原因或工具状态已变化后可重新验证，不无限轮询或重启。

可用的浏览器补验必须执行同一套生产Canvas/规则，明确标注平台。仍可修已复现游戏bug、完成素材入包和提交当前成果；用户有权试玩开发入口。发布/合并条件若有未满足项据实说明；不声称真机流畅或永不卡死。

## 收尾记录

在项目已有状态文档附：选定规则版与解释边界、认可概念、生产清单/提示词/图集文件、实现与入口、自然终局证据、测试范围、真实截图平台、待验问题、commit/branch。保留记录的版本对应，后续运行变化后更新相应证据。直接对话交付，用户未要求不做网页反馈。
