# 规则已确认后的初始化包

## 工作产物与继续实现

复用项目现有规范位置。第一次建立的最小资料：

1. `brief.md`：规则真源/改编、首发模式、平台、目标阶段、已确认风格、用户决定、owner与禁止越界项。
2. `rule-map.csv`：规则条款→新主题→阶段/动作/数据→测试/证据；终局、同分、特殊卡、隐藏信息不能漏。
3. `capabilities.json`：矩阵每项首发适用性/占位/实现/验证分开，接口/运行入口/缺口/owner/退出条件；能用于生成待办，不自动宣布完成。
4. `asset-plan.csv`：逻辑ID、用途、源图/运行图、尺寸/锚点/alpha、图集坐标、状态；大素材与小图集分开。
5. `release-checklist.md`：从技能模板复制到项目后补候选版本、实际证据、签收人；不是一创建就打勾。

脚本 `scripts/init_boardgame.py` 只创建上述资料，默认dry-run，`--write`才写；复跑不覆盖已有文件，拒绝越出项目/不安全game ID。`--mode`可重复选择solo-ai/hotseat/online；online会启用房间/会话/权威验收，AI只在solo-ai模式默认启用，联机要原生电脑玩家时再声明。付费/云存档/兑换不因模板默认启用。

初始化资料后，在用户已授权的范围继续做可启动外壳，而不是以五个文件完成移植：大厅窄入口→准备页→游戏场景→结果页→返回；准备页声明真实支持的模式；规则帮助与菜单可进入退出；加载中/失败/资源缺失有出口。已有引擎和宿主接口优先复用，不创造第二套全局导航。

生成器只预填ID、名称和首发模式；已有引擎、规则条款、人数、画风、接口及验证证据由实际资料填入，不能因模板存在把它们算完成。WAIT等待政策默认只随online启用；离线需要专门等待机制时再显式启用，基本忙碌反馈和当前行动者提示仍属于FEEDBACK/SEAT。

## Placeholder的确切含义

每个占位要有：稳定ID、位置/接口、适用模式、预期最终行为、当前可见行为、禁用或开发门禁、负责人、移除条件、验证方法。实现状态可为MISSING / PLACEHOLDER / IMPLEMENTED；验证状态另为NOT_RUN / PASS / FAIL / BLOCKED / NOT_APPLICABLE。

|可接受开发占位|不能接受|
|---|---|
|有真实返回路径的帮助面板，明确规则内容尚缺；在B1前补足必要玩法说明|点击“规则”无反应，或打开另一款游戏的规则|
|未接云功能返回结构化UNAVAILABLE，UI显示未开放且不发成功动画|空函数return true；保存/解锁/发奖失败仍提示成功|
|缺图时用可读的开发纹理并在清单绑定最终资产|把临时几何图标、整屏概念图当成正式插画交付|
|未来联机入口隐藏或标未开放，能力manifest online=false|按钮写“在线多人”但实际启动本地AI|
|音效能力声明为未接；占位开关禁用并说明|设置里有开关但游戏从未调用音频服务|
|练习局单独的模式/结果出口，学习可退出重来|教学发正常奖励或首次打开就强制阻断受邀对局|

永久保留的简单代码绘制是设计选择，不因“没有贴图”必判placeholder。需插画/真实材质的已认可美术和用户明确要求独立生成的头像，不能悄悄以SVG/代码圆片替代。

## 模块和公共服务接口

按现有语言/引擎实现下列职责，不要求固定类名或目录：

- 规则数据/纯规则：创建局、合法动作、应用动作、状态校验、自然终局及分项结果；依赖注入随机/时间，不依赖渲染/平台存储。
- AI：只读合法观察→意图；规则引擎最终判合法；难度不能靠偷窥隐藏信息。
- 会话：mode、match身份、动作/请求、存档、恢复与生命周期；UI不自己扣钱算分。
- 呈现：布局/输入/事件回放/反馈；显示态与权威态明确，能处理待确认与失败。
- 资源：源素材、运行资产、主题catalog与加载/释放；分包下载后才能使用其资源。
- 宿主adapter：入口、能力、设置、持久化/结果、退出；公共UI不import具体游戏规则。

未接公共服务时返回可判别能力状态，不伪造业务成功。以保存为例，真实持久化成功/失败与内存快照分别返回；失败保留继续游戏/重试路径。联机的unknown不等同failed，先查同requestId和当前match。

## 整包派工

以“一个可用流程”分工，例如规则与正常终局包、产品外壳与素材接入包、联机恢复包、发布候选验证包。依赖紧密的writer/序号/AI门禁同owner完成，公共文件单写入；独立工作才并行。每包写目标、范围/接口、验收、未测和回报方式，数量与授权服从项目配置。局部QA通过不关闭上层完整目标。
